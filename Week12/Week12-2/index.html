Monday practice: useState

The code challenge, the video lecture challenge, the three study guide exercises and the practice from the last slide.

M1

Code challenge: counter with history

CounterWithHistory.jsx

Goal: Build a counter with +1, −1 and Reset, show the last 5 values, and add an Undo button. Use two state variables: count and history.

Result: The history is a new array every time ([...prev, next].slice(-5)), never changed in place. Undo steps back one value and is disabled when there is nothing to undo.

M2

Video lecture challenge: café order

CafeOrder.jsx

Goal: Three menu items, each with a − and a + button. A quantity can never go below 0, and the total is quantity × price.

Result: One state object holds every quantity. The − button is disabled at 0, and the total is calculated during render, so it is never stored in state.

M3

Toggle visibility

ToggleDetails.jsx

Goal: A “Show details” / “Hide details” button that shows and hides a paragraph with boolean state.

Result: The updater prev => !prev flips the value, and aria-expanded tells screen readers whether the text is open.

M4

Add and remove list items

StudyList.jsx

Goal: An input and an Add button that add items to an array in state, and a ✕ button on each item that removes it.

Result: Spread adds a new item and filter removes one. Each item has a stable id as its key, never the array index.

M5

Lifting state up

ScoreBoard.jsx

Goal: A parent ScoreBoard with two PlayerScore children that shows the combined total.

Result: The parent owns both scores and passes each child its value and callbacks, so it can show the total and who is leading.

M6

Practice: live word counter

WordCount.jsx

Goal: The practice from the last slide: count words and characters while the user types.

Result: Only the text is state. Words, characters and reading time are derived from it during render.

Friday practice: useEffect

The code challenge and its bonus, the three study guide exercises and the practice from the last slide. Every effect that starts something (a request, a timer) stops it again in its cleanup.

F1

Code challenge: GitHub profile card

GitHubUser.jsx

Goal: Fetch a GitHub profile in useEffect when the username changes. Show the avatar, bio, followers and repos, with loading and error states. Bonus: cancel the old request with AbortController.

Result: The effect depends on [username]. A wrong name (404), the rate limit (403/429) and network errors each get their own message, and the cleanup aborts the old request.

F2

Bonus: search while typing (debounce)

DebouncedSearch.jsx

Goal: Search GitHub users as you type, but only send a request when typing stops for 500 ms.

Result: Each key press runs the cleanup of the previous effect, which clears its timer and aborts its request. Only the last value is sent.

F3

Sync document.title

TitleSync.jsx

Goal: Update document.title whenever the input changes.

Result: The effect runs after each change to name, and the cleanup puts the old title back.

F4

Fetch data on mount

FetchUser.jsx

Goal: Fetch a user from JSONPlaceholder once when the component mounts, with loading and error states.

Result: The empty dependency array [] runs the effect once. The ignore flag drops an answer that arrives after unmount.

F5

Stopwatch

Stopwatch.jsx

Goal: A stopwatch with Start, Stop and Reset, using setInterval inside an effect.

Result: The interval only exists while running is true, and clearInterval in the cleanup stops it.

F6

Practice: character count with an effect

CharCount.jsx

Goal: The practice from the last slide: use an effect to keep a character count in state.

Result: It works, but it renders twice per key press. text.length during render (like M6) is the better way, and the comment in the code says why.
